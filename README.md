## 실행 설계: 기존 기능 보호

기존 단일 `<script>`는 서로의 변수와 함수를 바로 참조하는 약 4,500줄의 즉시 실행 함수(IIFE)입니다. 이를 성급하게 독립 ES 모듈로 전환하면 실제 작동하는 지형·네트워크·게임 루프가 끊길 수 있습니다. 따라서 이번 단계에서는 기능별 원본 코드 조각을 `src/game/`에 보관하고, `manifest.json` 순서로 *원본과 동일한 한 실행 스코프*에 결합합니다. 이는 정적 파일 서버나 GitHub Pages에서 실행 가능하며, npm 외부 패키지 / CDN 빌드 도구를 요구하지 않습니다.

- **소스코드**: `src/game/`에서만 수정하고 `dist/game.bundle.js`는 직접 편집하지 않습니다.
- **CSS**: 기능 파일이 `index.html`에서 개별 연결됩니다. CSS의 불변 순서를 유지합니다.
- **데이터**: 기존 일반 아이템 키·가격·레벨 구조를 유지합니다. 황금 5성의 재고 키는 별도 `gold:<아이템키>`이며, 기존 프로필에 `goldKnown`, `specialTitles` 두 속성만 추가합니다. 기존 기록은 그대로 불러올 수 있습니다.
- **배포**: `index.html`, `styles/`, `dist/game.bundle.js`를 동일한 폴더 구조로 업로드하면 됩니다. `src/`와 `scripts/`는 소스 및 개발용입니다.

### 확인 상태

`npm run check`는 JavaScript 문법, 구성 파일 누락, HTML ID 중복 및 JS→HTML ID 참조, CSS 괄호를 검사합니다. v1.0 분리 직후 게임 JS 본문은 원본과 **바이트 단위로 동일**했습니다. v1.1은 신규 기능 추가로 변경되어 더 이상 원본과 동일하지 않습니다. 실제 멀티플레이 MQTT 접속·모든 모바일 기기에서의 3D 플레이까지 자동 검증하는 것은 별도 현장 테스트가 필요합니다.

### 사용 시 주의

- `src/game/` 파일은 ***독립 실행 가능한 ES 모듈이 아닌*** 빌드 입력 소스입니다. 다른 파일의 공유 변수에 의존합니다.
- 레이아웃을 확장할 때 CSS는 `styles/`에만 추가하세요. 인라인 스타일 6개를 외부 CSS로 옮겨 놓았습니다.
- 단일 JS 번들로 묶어도 브라우저 실제 코드 실행은 원본과 같으며, 신규 기능을 도입할 때는 이 코드 맵을 갱신해야 합니다.

- 거리별 알림은 각각 별도의 진입/퇴장 상태를 가지며, **20m와 10m 알림을 구분**합니다. 레벨 8·9는 10m 내에 두 안내가 동시에 나타날 수 있습니다.

- 기존 5성만 감지합니다(진짜 채집물, 실제 화면에 생성됨, 미채집, 높이차 ≤6m). **기존의 식물 위치·출현 확률·채집/판매·랭크 승급 조건은 그대로**입니다.

- 탐지 능력은 자신의 화면만 변경되는 로컬 알림이므로 저장 데이터나 멀티플레이 메시지 형식에 새 필드가 필요하지 않습니다.
- 탐지 메시지는 **방향이나 정확한 위치를 공개하지 않습니다.**

## v1.1 게임 내 이용 방법

- 숲속의 비밀 입구는 기존 산 지형에서 결정적 시드로 선정되며, **지도·HUD에는 표시되지 않습니다.** 여러 플레이어가 동일한 새 버전에 접속하면 동일한 후보가 사용됩니다.
- 발견한 입구에서 **동굴로 들어가기** 버튼을 누르면 바위 통로로 들어갑니다. 가장 안쪽 불상에 접근해 **공양하기**를 선택할 수 있습니다.
- 일반 5성/황금 5성을 1개 바치고 절 애니메이션이 끝나면 재료가 소모됩니다. **황금 5성만 특별 칭호 지급** 대상입니다.
- **✦ 특별 칭호** 버튼에서 여러 칭호 중 하나를 장착하거나 해제합니다. 이름 위에 황금색으로 표시되며 레벨·등급은 그대로 유지됩니다.
- 황금 5성은 기존 5성 개체의 색상만 달라지는 희귀 변형(5성 출현 주기의 약 0.25%)이고, **상점에서는 절대로 판매할 수 없습니다.** 일반 5성은 기존대로 판매됩니다.
- 3·4성 품목에 황금 5성이 추가되지는 않습니다. 제공한 칭호 이름 중 등급에 맞지 않는 품목은 원본 품목의 희귀도를 유지하여 제외합니다.

## GitHub Pages 최신 코드 올리기

1. 이 프로젝트 ZIP을 압축 해제합니다.
2. GitHub 저장소에서 프로젝트의 `index.html`, `styles/`, `src/`, `scripts/`, `dist/` 등 동일한 상대경로를 유지하여 업로드합니다. **`dist/game.bundle.js`도 반드시 교체하세요.** 이 파일이 실제 실행 코드입니다.
3. 중복 파일을 만들지 않도록 같은 경로의 기존 파일을 대체한 후 Commit changes를 누르세요.
4. Settings → Pages에서 기존 main/(root) 배포 설정을 유지합니다. 배포 완료 후 브라우저에서 강력 새로고침하여 변경된 코드가 반영되었는지 확인하세요.
5. 기존 저장 기록을 백업하려면 게임의 **기록 저장** 기능으로 JSON 파일을 먼저 내보내세요.

## 구현상 제약

- GitHub Pages는 정적 호스팅이고 기존 멀티플레이는 **익명 공용 MQTT**입니다. 서버 검증 없는 브라우저 클라이언트만으로는 거래 조작·동시 접속 악용·서로 다른 기기의 저장 동기화를 완벽히 방지할 수 없습니다. 따라서 칭호의 영구성은 **현재 브라우저 프로필과 수동으로 내보내는 JSON 기록 기준**이며, 별도 백엔드 없이 계정 서버의 영구 기록은 보장되지 않습니다.
- 공개된 웹 소스의 위치 선택 알고리즘을 분석하면 동굴 위치를 역산할 수 있으므로 절대적인 은닉은 불가능합니다. 실제 지도에는 표시되지 않고 개발 보고서에도 구체 위치를 적지 않습니다.
- 정적·회귀 테스트는 통과했지만 브라우저 WebGL·MQTT 실제 통합 플레이는 이 환경에서 차단되어 현장 확인이 필요합니다.

### v1.2.1 안내 · 황금 5성 도감

v1.2.2에서는 **미발견 황금 5성은 일반 도감의 미발견 카드와 동일한 원본 3D 아이콘을 회색 실루엣으로 표시**합니다. 카드의 금색 테두리·금빛 배경 및 `???` 이름은 유지하고, **발견한 황금 5성에만 금색 모델**을 사용합니다. 일반 도감의 미발견 실루엣은 변경하지 않았습니다.

실제 게임 화면이나 사용자 저장 데이터는 외부 WebGL 실행 제한으로 직접 검증하지 못했습니다. PNG 불상 참고 이미지는 원본 3D 코드에 명시된 기본 도형을 별도 렌더러로 재구성한 것이며, 게임 화면 캡처가 아닙니다.
